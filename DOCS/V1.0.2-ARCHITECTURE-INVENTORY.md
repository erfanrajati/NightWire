# NightWire v1.0.2 Architecture Inventory

This document began as the v1.0.2 characterization baseline and now tracks the compatible source tree as the modular Drop/Core milestones land. Historical legacy-file behavior is called out separately from newly created Drops.

## Snapshot and system boundary

- `VERSION` and `pyproject.toml` both identify the application as `1.0.2`.
- NightWire is one Python process serving one browser application over HTTP.
- The backend is a Starlette application run by Uvicorn. AnyIO supports file streaming and thread handoff; `qrcode` generates SVG QR codes.
- The frontend is plain HTML, CSS, and JavaScript. There is no bundler, frontend framework, service worker, database, message broker, or external service.
- Files and their lifecycle metadata survive a process restart. Clipboard history and client presence do not.
- The server binds to `0.0.0.0` and is designed for a trusted local network. It does not provide TLS, accounts, roles, or a global authentication layer.

```text
Browser: /files, /clipboard, /clients, /drop/{filename}?key=...
        │
        ├── JSON requests and polling
        └── streamed upload/download bodies
                │
          Starlette / Uvicorn
          ├── route handlers
          ├── in-memory clipboard registry
          ├── in-memory client registry
          └── one-second cleanup thread
                │
          Core storage root
          ├── .nightwire-objects/ (opaque permanent content)
          ├── .nightwire-object-metadata/ (security results)
          ├── .nightwire-uploads/ (isolated temporary content)
          ├── compatible legacy user files
          └── .nightwire-metadata.json
```

The module-level locks `_FILES_LOCK`, `_CLIPBOARD_LOCK`, and `_CLIENTS_LOCK` serialize access shared between request handling and the cleanup thread. There is no multi-process coordination, so running multiple workers against the same directory would not share clipboard/client state and would not coordinate in-memory metadata.

## Backend entry point

The root `app.py` is a compatibility alias and executable launcher for `nightwire.app.runtime`, preserving existing imports and monkeypatch-based integrations. Runtime composition and HTTP adaptation live in `nightwire.app`; resolved configuration, logical object storage, streaming transfers/progress, lifecycle decisions, capacity contracts, and security inspection come from `nightwire.core`; the Drop domain, lightweight metadata repository, file service, clipboard facade, client visibility, and route/static/lifecycle registration live in `nightwire.drop`; processor contracts live in `nightwire.processors`; and `nightwire.app.bootstrap` builds the Starlette application through the shared module-registration contract.

At import time it:

1. imports centrally resolved application, static, version, and files paths;
2. creates the files directory;
3. reads the version string;
4. initializes process-local registries and locks;
5. loads file lifecycle metadata from disk; and
6. passes its handler mapping and middleware to the application bootstrap.

When executed directly, `main()` reads `PORT`, prints local/network addresses and the storage path, and starts Uvicorn on `0.0.0.0`. Uvicorn is configured with no access log, a backlog of 2,048, a 30-second keep-alive timeout, and no server header.

## HTTP route inventory

The source registers the following routes. JSON and file responses are marked `Cache-Control: no-store`; the global middleware also supplies content-type, referrer, frame, and content-security headers.

| Method | Path | Handler/owner | Current behavior |
| --- | --- | --- | --- |
| `GET` | `/` | `root` | `307` redirect to `/files`. |
| `GET` | `/files` | `page` | Serves `static/index.html`; the browser selects the Files view. |
| `GET` | `/clipboard` | `page` | Serves the same HTML shell; the browser selects Clipboard. |
| `GET` | `/clients` | `page` | Serves the same HTML shell; the browser selects Clients. |
| `GET`/`HEAD` | `/static/{path}` | Starlette `StaticFiles` | Serves assets rooted at `static/`. Static responses receive explicit no-store caching. |

### Information and presence

| Method | Path | Handler | Input | Output and state effect |
| --- | --- | --- | --- | --- |
| `GET` | `/api/info` | `server_info` | None | Version, hostname, resolved files directory, fixed limits, and detected network URLs. No mutation. |
| `GET` | `/api/devices` | `list_devices` | None | Server record plus non-stale browser records. Opportunistically purges clients older than 18 seconds. |
| `POST` | `/api/clients/heartbeat` | `client_heartbeat` | JSON `client_id`, optional `platform` and `mobile`; User-Agent header | Creates or refreshes an in-memory client record and returns the current device list. Payload limit: 8,192 bytes. |
| `GET` | `/api/qr?url=...` | `qr_code` | Absolute HTTP(S) URL, maximum 2,048 characters | Generates an SVG QR code. It accepts any syntactically valid HTTP(S) authority; it does not restrict the target to NightWire hosts. |

### Files

| Method | Path | Handler | Input | Output and state effect |
| --- | --- | --- | --- | --- |
| `GET` | `/api/files` | `list_files` | None | Purges expired files, lists visible files newest-modified first, and returns filesystem total/used/free bytes. |
| `PUT` | `/api/upload?filename={name}` | `upload_file` | Raw body; optional lifetime and Base64 password headers | Streams through Core, issues a Drop Access Key, persists only its salted digest, and returns a complete one-time share URL with `201`. |
| `PATCH` | `/api/files/{filename}` | `patch_file` | JSON containing only `expires_in_seconds` | Replaces the countdown relative to the update time and saves metadata. Password changes are rejected. |
| `GET` | `/drop/{filename}?key=...` | `drop_share_page` | Filename and Access Key | Validates the bearer key and serves the recipient Drop page. |
| `GET` | `/api/drops/{filename}?key=...` | `drop_share_info` | Filename and Access Key | Returns recipient-safe metadata after authentication. |
| `GET`/`HEAD` | `/download/{filename}?key=...` | `download_file` | Filename and Access Key | Authenticates and downloads a new Drop. Compatible legacy files have no key requirement. Password-protected Drops return `401` after key validation. |
| `POST` | `/api/files/{filename}/download?key=...` | `download_protected_file` | Access Key and JSON `password` | Verifies both credentials and returns the file. |
| `DELETE` | `/api/files/{filename}` | `delete_file` | Optional JSON `password` | Deletes the file and metadata. A protected file requires the correct password. |

File names must be a single non-empty basename. Path separators, traversal, `.gitkeep`, `.nightwire-metadata.json`, `.nightwire-objects`, `.nightwire-uploads`, legacy upload temporaries, and metadata temporaries are reserved.

### Clipboard

| Method | Path | Handler | Input | Output and state effect |
| --- | --- | --- | --- | --- |
| `GET` | `/api/clipboard?since_revision={n}` | `list_clipboard` | Integer revision; default `-1` | Returns the full public snapshot only when the revision differs. Otherwise `changed` is false and `entries` is empty. Expired entries are purged first. |
| `POST` | `/api/clipboard` | `share_clipboard` | JSON `client_id`, `text`, optional `expires_in_seconds`, optional `password` | Prepends one entry, bounds history to 40, increments the revision, and returns `201`. Payload limit: 160,000 bytes. |
| `PATCH` | `/api/clipboard/{entry_id}` | `patch_clipboard` | JSON containing only `expires_in_seconds` | Replaces the countdown and increments the revision. Password changes are rejected. |
| `POST` | `/api/clipboard/{entry_id}/unlock` | `unlock_clipboard` | JSON `password` | Returns plaintext after password verification; no state mutation. In v1.0.2, a wrong password raises an uncaught `PermissionError` instead of being translated to a JSON `403`. |
| `DELETE` | `/api/clipboard/{entry_id}` | `delete_clipboard` | Optional JSON `password` | Deletes one entry and increments the revision. Protected entries require the password. |
| `DELETE` | `/api/clipboard` | `clear_clipboard` | None | Clears all entries and increments the revision only when no protected entry exists; otherwise returns `409`. |

Clipboard entry IDs are 32 lowercase hexadecimal characters. Client IDs must be 8–128 characters, begin with an alphanumeric character, and otherwise contain only alphanumerics plus `.`, `_`, `:`, or `-`.

## File lifecycle metadata

The on-disk JSON object is keyed by filename. Each value has this internal shape:

```json
{
  "example.txt": {
    "created_at": "2026-09-13T00:00:00+00:00",
    "expires_at": null,
    "object_id": "0123456789abcdef0123456789abcdef",
    "checksum_sha256": "64-lowercase-hexadecimal-characters...",
    "size": 1234,
    "security": {
      "verdict": "unscanned",
      "detected_mime": "text/plain",
      "declared_mime": "text/plain",
      "mismatches": []
    },
    "access_key_digest": {
      "algorithm": "sha256-v1",
      "salt": "base64...",
      "digest": "base64..."
    },
    "password": {
      "salt": "base64...",
      "digest": "base64..."
    }
  }
}
```

| Field | Meaning |
| --- | --- |
| `created_at` | UTC ISO-8601 creation timestamp. Uploads use server time. Files discovered without metadata use filesystem modification time. |
| `expires_at` | UTC ISO-8601 deletion deadline. New Drops always set it; compatible legacy files may use `null`. |
| `access_key_digest` | Salted, domain-separated verifier for a new Drop's 256-bit key. Raw keys are never persisted. |
| `object_id` | Stable logical identity for new physically stored content. Absent for compatible legacy root files. |
| `checksum_sha256` | SHA-256 calculated while receiving a new upload. Absent for legacy files without integrity metadata. |
| `size` | Byte count captured when the upload is finalized. |
| `security` | Persisted verdict, byte-derived MIME evidence, extension/declared comparisons, scanner identity/version/signature metadata, findings, and inspection time. |
| `password` | `null` or a 16-byte random salt and 32-byte `scrypt` digest, both Base64 encoded. Plaintext is not stored. |

Metadata loading is tolerant: invalid JSON results in an empty registry; malformed entries, unsafe names, and malformed password records are ignored or sanitized. Writes serialize the full in-memory mapping with sorted keys and atomically replace the metadata file.

The public file record exposes `name`, `size`, filesystem `modified`, logical `created_at`, `expires_at`, `access_key_required`, `password_protected`, `checksum_sha256`, the complete recipient-safe `security` result, compatibility `security_verdict`/`detected_mime` projections, `download_confirmation_required`, and `download_url`. Object IDs and credential verifiers never leave the backend API.

Files copied directly into the shared directory are visible immediately. Their default record is created lazily in memory with unlimited retention and no password; that default is not necessarily written to disk until a later metadata-saving operation.

## Lifecycle rules

- New Drops require a positive lifetime from 60 seconds through 31,536,000 seconds and default to 3,600 seconds.
- Anonymous internet-facing Drops have a hard 86,400-second maximum.
- Compatible legacy files may retain `null` expiration until replaced or updated.
- Clipboard entries default to 600 seconds (10 minutes).
- Password protection is optional and may only be set at creation.
- After creation, any connected client can change an item's countdown without a password.
- A password cannot be added, changed, or removed after creation.
- Protected access and deletion require the password; listing and countdown changes do not.
- Passwords are limited to 256 characters and use `scrypt` (`N=2^14`, `r=8`, `p=1`, 32-byte output) plus constant-time digest comparison.

Uploads stream request chunks through `CoreTransferService` without an application-level size limit. SHA-256 and byte count are accumulated during the stream. The service returns a pending upload before permanent content exists; finalization separately promotes it by atomic rename. The logical destination is checked for protected overwrite both before streaming and immediately before finalization to close the race between concurrent requests.

Object-backed downloads also stream through `CoreTransferService`. Both directions emit started/transferring/terminal events to optional hooks and a 256-transfer, thread-safe latest-state store. Upload responses and object-backed download headers expose the opaque transfer ID for future correlation; there is no public progress-listing endpoint yet.

Core byte-signature/structure detection is authoritative over browser MIME. Extension and declared-MIME differences are recorded. The verdict model supports `clean`, `suspicious`, `malicious`, `scan_failed`, and `unscanned`; without a configured scanner, matching evidence is `unscanned` and mismatches are `suspicious`. Core policy retains every verdict in opaque storage, blocks malicious objects from risky processors, and requires deliberate confirmation for malicious downloads.

Processor execution results carry a stable processor name/version identity, normalized `succeeded`/`failed`/`skipped` status, metadata, timing, error details, and typed references to zero or more derived Core objects. The registry keeps one active version per stable processor name and verifies returned identity. Security-sensitive execution is represented by object-ID-based sandbox requests with bounded resources and networking disabled by default. Only a deny-only executor exists, so this abstraction does not enable host command execution.

## Clipboard state

`_CLIPBOARD_ENTRIES` is a newest-first process-local list. An internal entry contains:

- UUID-derived `id`;
- normalized plaintext `text`;
- originating `client_id`, display `source`, and request IP address;
- `created_at` and optional `expires_at`; and
- an optional password record using the same format as files.

Public snapshots replace protected plaintext with `null` but expose its character count and lifecycle/source fields. Unprotected plaintext is returned directly.

`_CLIPBOARD_REVISION` starts at zero on every process start. It increments on add, countdown update, successful single deletion, clear, and each purge operation that removes one or more expired entries. Adding past the 40-entry limit truncates old entries as part of the same revision change. Clearing also increments the revision when the list is already empty. Unlocking does not increment it.

## Client presence state

Each heartbeat updates `_ACTIVE_CLIENTS[client_id]` with request IP, inferred device type, operating system, browser/version, display label, connection time, last-seen time, and an epoch value used for expiry. Existing IDs retain their original `connected_at` time.

The server is synthesized as the first device on every response and is not stored in the registry. Browser clients are stale after 18 seconds. There is no dedicated presence thread: stale clients are removed opportunistically by a heartbeat or device-list request.

User-Agent parsing is a local heuristic in `nightwire.app.runtime`; there is no parser dependency. It includes explicit handling for common phones/tablets, Windows/macOS/Linux/ChromeOS, and major browsers.

## Cleanup jobs

### Expired items worker

Starlette's startup hook starts one daemon thread named `nightwire-cleanup`. Once per second it:

1. acquires the file lock, delegates expiration/missing-item classification to `CoreLifecycleService`, removes affected files and metadata, and removes inactive temporary uploads older than 24 hours while excluding active transfer IDs; then
2. acquires the clipboard lock, delegates expiration classification to the same service, and removes expired entries, incrementing the revision once when the list changes.

Exceptions are printed as cleanup warnings and the loop continues. The shutdown hook sets a stop event and joins the thread for up to two seconds.

Relevant request and state functions also purge before listing, updating, unlocking, downloading, or deleting. Expiry therefore does not rely solely on the timing of the background thread.

### Inactive-client cleanup

Client TTL cleanup is separate and synchronous. Heartbeats and device reads remove records whose last-seen age is greater than 18 seconds.

## Frontend entry points and update model

`static/index.html` is the manager entry point. It contains all three page sections, lifecycle/password/share-link modals, and toast UI. It loads:

- `/static/styles.css?v=1.0.2`; and
- `/static/app.js?v=1.0.2`.

`static/app.js` is the shared ES-module shell and imports `static/drop.js`. The Drop module starts immediately, binds events, derives the route from `window.location.pathname`, initializes controls/state, and concurrently loads server info, files, a client heartbeat, and clipboard history. This ownership split does not redesign the v1.0.2 UI.

`static/drop-share.html` and `static/drop-share.js` form the recipient entry point. The complete share URL authenticates metadata and download access. The manager holds a newly issued raw key only in page memory; it is not written to browser storage.

Client-side navigation intercepts links and uses `history.pushState`; direct navigation still works because all three page routes return the same shell. The accepted UI routes are `files`, `clipboard`, and `clients`; any other parsed route falls back to Files in JavaScript.

The browser state object holds the current files/info/devices, upload map, clipboard snapshot/revision, clipboard-watch flags, current route, and active modal actions. Only the generated client ID is written to `localStorage`; other state is reconstructed after reload.

| Browser activity | Mechanism | Cadence |
| --- | --- | ---: |
| Presence and device list | `POST /api/clients/heartbeat` | 2.5 seconds |
| Clipboard synchronization | revision polling via `GET /api/clipboard` | 1.2 seconds |
| File synchronization | `GET /api/files` | 4 seconds |
| Countdown labels | local DOM refresh, followed by a reload when expiry is reached | 1 second |
| Optional clipboard observation | secure-context `navigator.clipboard.readText()` | 1.5 seconds |

Uploads use `XMLHttpRequest` to expose progress and cancellation. Downloads use a direct anchor for unprotected files and `fetch` plus a Blob for password-protected files. Clipboard write prefers `navigator.clipboard.writeText()` with a hidden-textarea fallback. Clipboard reading requires both a secure context and browser permission; paste/copy events also drive sharing recommendations.

## Security middleware

Every HTTP response receives defaults for:

- `X-Content-Type-Options: nosniff`;
- `Referrer-Policy: no-referrer`;
- `X-Frame-Options: DENY`; and
- a self-only CSP for scripts, styles, connections, and most content, with `data:`/`blob:` images allowed.

The QR response overrides CSP to disallow all default sources and allow its inline SVG style. Static assets are explicitly non-cacheable. The application does not authenticate user identities or encrypt transport/content; bearer Access Keys gate new Drop metadata/downloads and optional passwords add a second check.

## Launchers, installers, and updater

| File | Platform/use | Current behavior |
| --- | --- | --- |
| `run.sh` | Unix source tree | Requires `uv`, chooses `NIGHTWIRE_PORT`, then `PORT`, then `8080`, and executes `uv run --locked python app.py`. |
| `run.bat` | Windows source tree | Same port precedence, requires `uv`, and pauses after errors. |
| `install.sh` | Linux/macOS install or upgrade | Stages the release manifest, installs `uv` when missing, replaces application files, preserves runtime paths, verifies byte equality, syncs a locked no-dev `.venv`, and writes `/usr/local/bin/nightwire` by default. Uses `sudo` only when target parents are not writable. |
| `install.ps1` | Windows install or upgrade | Stages/validates the manifest, installs `uv` when missing, replaces application files, preserves runtime paths, verifies SHA-256 hashes, syncs a locked no-dev `.venv`, creates `nightwire.ps1` plus `nightwire.cmd`, and adds the bin directory to the user PATH when needed. |
| `update-existing.sh` | Unix recursive repair/update | Replaces an existing tree from a staged manifest, preserves source/runtime paths, verifies the replacement, and optionally runs `install.sh` with `--install`. |

The Unix and Windows installers preserve top-level `files/`, `.venv/`, `.env`, and `.env.*`. `update-existing.sh` additionally preserves `.git/`. The Unix installer copies missing source files into the destination `files/` directory on a first install from a separate source without overwriting existing names.

The installed `nightwire` launcher accepts `-p`/`--port` and validates the range 1–65,535. It runs the installed, locked environment with `--no-sync`. No service manager entry, autostart job, firewall rule, or TLS configuration is installed.

The current release manifest contains backend/runtime files, launchers/installers, the six primary frontend files, tests, and `files/.gitkeep`. It does not contain `DOCS/`, `static/assets/logo.svg`, the runtime metadata file, user uploads, `.venv`, or local environment files.
